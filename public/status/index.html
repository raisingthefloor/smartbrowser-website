Where things stand

A first-draft proof of concept exists and runs entirely on a laptop. The field around it is moving fast. Here is what is real, what is projected, and what is next.

The proof of concept

To find out whether the idea was more than hand-waving, Gregg Vanderheiden asked his son James, who is not an AI specialist, to try to build one with him. In one person-month, half of it analysis and half programming, they had a first-draft smart browser that:

  • runs entirely locally on a five-year-old Mac (M1 Max) with Qwen 2.5 14B in about 12 GB of memory, sending nothing off the device;
  • on pages that fail WCAG, satisfies roughly 50% of Level A criteria, 50% of Level AA, 35% of Level AAA, and about 50% of the requirements in the current WCAG 3.0 drafts;
  • uses the model only where judgment is needed, and deterministic repairs and style changes everywhere else;
  • marks every change it makes, shows the original on hover, and can be switched off for a straight-through rendering of the page.

Caveats, in the words of its author: this is a rough first pass; the first half is always the easiest; it is still being tested; there is a long way to go. It also appears that more will be possible, sooner, than expected.

The code will be published under an open-source license once it is in shape for others to run. See Code.

What the proof of concept can adjust today

These are the 85 settings in the proof of concept's panel, as a person would see them, grouped the way the panel groups them. Each one is something the browser does to a page on that person's behalf. Many go beyond anything WCAG requires.

Text 12 settings
Underline links
Underline all links, so color is not the only cue.
Text font
Changes all text on the page to the selected font. “Select Other” opens a list of all the fonts installed on the device.
Text size
Increase all text sizes on the page proportionately (equally). 0 = leave as authored.
Minimum text size
Increase any text smaller than this to this size. 0 or empty = no minimum.
Line height
Space between lines of text. 0 = leave as authored.
Letter spacing
Space between letters in words. 0 = leave as authored.
Word spacing
Space between words. 0 = leave as authored.
Paragraph spacing
Space after each paragraph. 0 = leave as authored.
No double-justified text
Blocks of text are justified left or right only. None are both.
Reflow text
Reflows text within paragraphs and table cells, within the page boundary, so there is no scrolling to read a single line (no horizontal scrolling for horizontal text, no vertical scrolling for vertical text).
Visibly separate blocks
Insert space and a hairline above every meaningful block (headings, regions, articles, navigation) so blocks are visibly separate.
Mark emphasis with text
Add a character in front of bold, italic, caps or underlined text.
Color and contrast 10 settings
Minimum text contrast
Increase the contrast of text against its background if it falls below this value.
Maximum text contrast
Decrease the contrast of text against its background if it falls above this value.
Background color
Override the page/background color. Empty = leave as authored.
Text color
Change all text to this color.
Color theme
Set the color theme to Dark, Light, or High Contrast.
Color vision
Shift colors to make them distinguishable from each other with color blindness.
No color-only cues
Add a non-color visible cue for every color-only cue.
Outline faint controls
Add an outline around links, buttons and fields whose own colors give under 3:1 against their background.
Outline shadow-only elements
Add an outline to elements that stand out only by a drop shadow.
Visual once-over (vision)
After a theme is applied, the vision model looks at the result and points at anything still unreadable or unthemed; those spots are fixed at the element that supplies the background.
Reading 6 settings
Make all abbreviations clickable items
Make each abbreviation a clickable element that pops up its expansion, or a list of best guesses if it is not known.
Show abbreviation meaning
Show spelled-out abbreviations the first time they appear, if not already shown (show a clickable ? with best guesses if not sure).
Make all idioms clickable items
Make all idioms clickable elements that pop up the meaning of the idiom.
Explain numbers
Write numeric alternatives beside non-standard numbers, for the types checked below.
Convert units
Convert measurements and temperatures and write them beside the original, as checked below.
Variable text simplification
Convert all text that is above the selected level of simplicity to the selected level.
Images 3 settings
ALT text
Choose which images to describe in alt text, if not already described in ALT.
Alt text detail
How detailed image descriptions should be at first. (You can always right-click any image and ask any question about it.)
Charts as tables (vision)
Chart images have a table inserted after them presenting the data in the chart.
Keyboard and pointer 10 settings
Ensure keyboard navigation
Ensure all items that can be acted on can be reached with standard keyboard navigation techniques.
Fix the Tab order
Fix the Tab and arrow-key navigation order.
Show shortcut key tags
Choose a key to show a small tag beside each element that has a keyboard shortcut, naming the key, and how long the key needs to be held down.
Fix single-key page shortcuts
Turns off single-key shortcuts, or requires a modifier key to activate them.
Flash what I activate
Flash the element I just clicked or activated with Return or Space.
Follow action
When an action reveals a dialog or new content elsewhere on the page, move keyboard focus to it.
Infinite scrolling
Change how an infinite-scrolling page works.
Unblock paste
Allow paste in fields that do not ordinarily allow paste.
Highlight what I point at
Place a ring around whatever the mouse pointer is over.
Allow browser explore
Allow this browser to explore pages in a hidden offline browser to better understand how they operate (reads page code only, does not click things), and set how long it should try before giving up and displaying the page as best it can.
Page structure 16 settings
Repair page titles
Add missing or duplicate page titles using the page heading and site name.
Repair structure
Add missing markup for headings, lists and groups, and label links.
Add labels
Give a visible label to things with none (e.g. controls, images, unnamed regions).
Put visible label in the name
Ensure that the visible label is contained in the programmatically determinable name.
Collapse duplicate links
When two visually adjacent things link to the same location, keep only one.
Markup languages
Add language tags to the page and to any changes in language on the page.
Declare languages
When the page or a phrase is not in one of my selected languages, do the following.
Announce focus moves
Announce through the live region when the page moves the keyboard focus on its own.
Announce page updates
When the page adds a status or error message after loading (a form result, “saved”, “added to basket”), announce it through a polite live region so a screen reader hears it without hunting.
Announce when new page opens
When the page asks to open a new window after your click, announce it and then open it. If the page tries to open one on its own (a timer, a pop-under), it is blocked and you are asked if you want it.
Show where I am in a process
Unless the process is of unknown length or changes depending on my choices, show a banner with the steps and where I am in the process.
Explain disabled controls
For any disabled control, add text alongside it explaining why it is disabled and how to enable it, from the page’s own hints.
Consistent menus
When this page departs from the site’s own pattern seen earlier this session, arrange its menus to be as consistent with the others as possible, in the order of menu items and in the naming of items that go to the same place.
Announce page pattern changes
When this page departs from the site’s own habits seen earlier this session (navigation items in a different order or under different names, the help link moved or missing, a repeated block missing), add a note at the top describing the change.
Highlight preselections
If the page has preselected a visible checkbox or switch, highlight it so an easy-to-miss preselection is noticed.
Describe unusual input controls
When the page relies on any checked item below, say so at the top, with the keyboard alternative this browser provides where it has one.
Forms 3 settings
Form errors
When a form field is in error: programmatically tie its message to it, put a copy beside the field if the message sits elsewhere, add an icon and the word “Error” beside the color, and append how to fix it from the field’s own rules.
Restore my entries
When I come back to a page I filled in earlier this session, put back what I entered before (but never remember passwords or passcodes).
List field rules
Put each form field’s rules beside the field (required, the format, the length or range), as determined from the attributes the page enforces silently.
Timing 3 settings
Show me active if I am slow
When a server session has an expiry (its cookie) or the page runs an idle sign-out, keep the session alive with a quiet request to the page every few minutes, while I am present (window focused, recent input).
Time remaining
Show me the time remaining and whether and how I can extend it, but only as I ask for it below.
Reply display time
Show timed displays this much longer than the page would. Press Esc to hide.
Motion and stimulation 6 settings
Damp dangerous flashing
When flashing approaches the seizure threshold, freeze the flashing for 1 second.
Flash limit (flashes a second)
The rate above which flashing is slowed as it happens.
Mark live unaltered content
Mark, programmatically and with a red outline, any content that the browser currently cannot process and make accessible.
Pause animations
Pause motion the page starts on its own.
Block the page from vibrating
Stops the page from vibrating.
Calm mode (less color, no motion)
Images, video and picture backgrounds desaturated; every animation and transition paused; animated GIFs frozen; playing media paused; anything flashing more than once a second slowed.
Appearance 16 settings
Focus ring color
Color of the keyboard focus ring.
Focus ring thickness
Thickness of the keyboard focus ring drawn on the front.
Link underline color
Color of the link underline.
Link underline gap
Gap between the text and its underline, so the line does not touch the letters.
Link underline thickness
Thickness of the underline drawn under links.
SmartBrowser ALT mark
How text generated by the browser is marked.
Emphasis color
The color used by the color, bold + color, highlight and box re-styles.
Emphasis shown as
How emphasis is marked. “Marker” prepends a small glyph that a screen reader will read. “Re-style” restyles the text to stand out more.
Marker: bold
The glyph placed before bold-only text in marker mode.
Marker: caps
The glyph placed before all-caps text in marker mode.
Marker: italic
The glyph placed before italic-only text in marker mode.
Marker: underline
The glyph placed before underline-only text in marker mode.
Re-style as
In re-style mode, how the emphasized text is restyled (e.g. “bold + color” makes every italic run bold and colored).
Mark text that SmartBrowser changed
Mark every piece of text the browser wrote (rewritten sentences, spelled-out abbreviations, numeric equivalents) with a faint blue highlight.
Show text that SmartBrowser changed
When SmartBrowser changes text, the original text is shown on hover, so nothing the browser wrote passes as the author’s.
Show everything the SmartBrowser changed
Outline everything the SmartBrowser fixed on this page (every element given a role, a name, a language, a table marked as layout, every note it added) with a tag naming the fix, so the invisible repairs can be seen, for checking and for a screenshot.

What it meets, criterion by criterion

A table of every WCAG 2.2 success criterion and every WCAG 3.0 requirement, showing which the proof of concept meets on failing pages, which it does not yet, and how each is met, is being prepared for this page. It was asked for at TPAC and it is the right way to answer the fair question of how much is AI and how much is plain engineering.

The field

The hooks a smart browser needs are already in browsers, and vendors are shipping the on-device models that make the judgment steps possible.

  • Chrome ships a small model (Gemini Nano) inside the browser and exposes it to extensions through its Prompt API, part of Chrome's built-in AI. The model is downloaded once and runs on the device; no page data goes to Google. A web-facing version is in development.
  • Other engines. Firefox, Safari, and Edge are aware of this direction and each has on-device features of its own; none has committed to anything like a smart browser. Reaching them is part of the work.
  • Reader modes and simplification in every major browser already restyle pages for the reader, without AI. They show that users accept browser-side changes to pages when the user asked for them.
  • Agents that operate interfaces, the AI systems that can look at a screen and use it, are the general form of the info-bot idea and are advancing quickly outside accessibility.

What the TPAC room said

The idea was presented at the W3C's TPAC 2026 in a breakout, “The Browser as Universal Interpreter: A 30-Year-Old Idea Whose Time Has Come,” led by Mike Paciello and Gregg Vanderheiden with Steve Faulkner moderating. Engineers from Google Chrome, including the developer-relations lead for the Prompt API and an engineering director, were in the room, along with people from the BBC, Cisco, and W3C staff.

The response was interest plus hard questions: will it scale to a site like CNN's front page or to pages that update constantly; can a page inject a prompt that makes the browser rewrite the DOM and leak data; who is responsible for content the browser generated; what happens to site analytics; should sites be able to opt sensitive flows like login out of rewriting; how can non-deterministic output be tested or standardized; what does running a model on every page load cost in energy and battery; and does each feature need AI at all. Two suggestions came with the questions: a community group is the lowest-barrier way to start, and even one criterion lifted off authors is worth doing. Each question is now an open question with a place to work on it.

What is next

  • Publish the proof-of-concept code and the criterion-by-criterion analysis.
  • Draft an explainer with others that defines the smallest standardizable surface: the settings vocabulary a person carries from browser to browser, and what sites can declare about their pages.
  • Continue conversations with browser vendors toward a real prototype in a browser engine.
  • Explore a W3C community group if the community wants one.
  • Add power consumption and site opt-out to the list of things to get right, and follow up on a proposed standard for reporting accessibility problems back to sites so repairs do not have to be redone on every load.
